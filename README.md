# ERPLPH — ระบบรายงานคลังเวชภัณฑ์และพัสดุ ทุกคลังของโรงพยาบาล

แดชบอร์ดสำหรับผู้บริหาร รวมข้อมูลทุกคลัง แยกรายงานเป็น 4 กลุ่ม
**ยา · เวชภัณฑ์มิใช่ยา · พัสดุ · อื่น ๆ** โดยใช้หลักเกณฑ์การคำนวณชุดเดียวกันทั้งหมด

เผยแพร่ที่ `172.16.13.102/ERPLPH`

## ผู้ใช้และตัวชี้วัด (กำหนด 11 กันยายน 2569)

ผู้ใช้: รองผู้อำนวยการฝ่ายบริหาร และหัวหน้างานจัดซื้อ งานรับของ งานจ่ายของ
ขอบเขต: ทุกคลัง รวมครุภัณฑ์ งานจ้างเหมา ก่อสร้าง และงานช่าง

| ตัวชี้วัด | ข้อมูล | สถานะ |
|---|---|---|
| มูลค่าคงคลังรวม | ภาพคงคลังรายวัน | ตัวดึงพร้อม รอดึงจริง |
| ยอดใช้ต่อเดือน | ใบจ่ายสุทธิหักรับคืน | มีแล้ว (ยา) |
| ใกล้หมด | คงคลัง ÷ ยอดใช้เฉลี่ย | มีครบเมื่อได้ภาพคงคลัง |
| ใกล้หมดอายุ | วันหมดอายุรายล็อตในภาพคงคลัง | มีครบเมื่อได้ภาพคงคลัง |
| ของค้างนิ่ง | คงคลังที่ไม่มียอดใช้ | มีครบเมื่อได้ภาพคงคลัง |
| ใบ PO ค้าง | SKPO / SKPODTL เทียบ SKRECVDTL ทุกคลัง | รู้ที่อยู่ ยังไม่ได้ดึง |
| ซื้อซ้ำ | ใบสั่งซื้อทุกคลัง | รอนิยาม |
| ซื้อแล้วจ่ายเงินหรือยัง | ยังไม่ทราบ (น่าจะเป็นระบบบัญชี) | สำรวจด้วย `check_procurement_finance.bat` |
| ครุภัณฑ์ | ยังไม่ทราบว่ามีทะเบียนแยกหรือไม่ | สำรวจ |
| จ้างเหมา ก่อสร้าง งานช่าง | ใบรับไม่มีเลขคุมสัญญาแล้ว | สำรวจ |

ครุภัณฑ์และงานจ้างไม่ถูกใช้หมดไป จึงไม่ใช้สูตรเหลือพอใช้กี่เดือน ต้องดูมูลค่า
การเบิกจ่าย และงวดงานแทน

## ความสัมพันธ์กับ Stock5

โปรเจกต์นี้**แยกจาก Stock5 โดยสิ้นเชิง** และ**ไม่แก้ไฟล์ใดของ Stock5 เลย**
แต่ **ยืมเครื่องคำนวณมาใช้** ผ่าน [app/stock5_engine.py](app/stock5_engine.py)

| | Stock5 | ERPLPH |
|---|---|---|
| ขอบเขต | คลัง 2 คลังเดียว | ทุกคลัง (36 คลังที่มีของ) |
| รายการ | ยา ตามรูปแบบรหัส | 4 กลุ่ม ตาม MAINCATEGORY |
| ที่เก็บ | ไฟล์ JSON ทั้งก้อน | SQLite เติมทีละงวด |
| หน้าที่ | ส่งข้อมูลกระทรวง + รายงานคลังยา | รายงานผู้บริหารทั้งโรงพยาบาล |

**ทำไมไม่คัดลอกโค้ดคำนวณมา:** สูตร MOS การสอบทานรายล็อต และการแปลงหน่วย
ผ่านการตรวจกับข้อมูลจริงมาแล้ว ถ้ามีสองชุด วันหนึ่งจะคำนวณไม่ตรงกันแล้วไม่มีใคร
รู้ว่าฝั่งไหนถูก ระบบที่เกี่ยวกับการเงินรับความเสี่ยงแบบนั้นไม่ได้

โมดูลที่ยืม: `lot_reconciliation`, `monitor_units`, `special_units`,
`confirmed_units`, `drug_names` — **อ่านอย่างเดียว** และปฏิเสธการยืมโมดูลที่
เกี่ยวกับการส่งข้อมูลกระทรวงหรือการดึงข้อมูลของ Stock5

ตั้ง `STOCK5_HOME` ถ้า Stock5 อยู่คนละที่ ค่าเริ่มต้นคือโฟลเดอร์ข้าง ๆ กัน

## ทำไมต้องมีฐานข้อมูล

การสำรวจฐานข้อมูลจริง (11 กันยายน 2569) พบว่า

```
บรรทัดจ่าย 12 เดือน ทุกคลัง = 930,720 บรรทัด (21 คลัง)
คลัง 2 ที่ Stock5 ใช้อยู่    =  52,064 บรรทัด (5.6%)
```

Stock5 เก็บเป็นไฟล์ JSON ก้อนเดียวและเขียนใหม่ทุกรอบ ที่ 78,586 บรรทัดคือ 141 MB
ถ้าขยายเป็นทุกคลังจะกลายเป็นหลาย GB และต้องอ่านใหม่ทั้งหมดทุกครั้ง

[app/warehouse_db.py](app/warehouse_db.py) จึงเก็บเป็น SQLite และเติมเป็นราย
**งวด (เดือน × คลัง)** ดึงเฉพาะส่วนที่ยังไม่มี ไม่ต้องอ่านประวัติซ้ำ
โดยยกหลักการสำคัญของ Stock5 มาด้วย: งวดหนึ่งเขียนทั้งหมดหรือไม่เขียนเลย
เก็บ checksum และที่มาของทุกงวด และงวดที่ดึงไม่ครบจะไม่ถูกนำไปคำนวณ

### ยอดใช้สุทธิ (ผู้ใช้ตัดสิน 11 กันยายน 2569)

**ยอดใช้ = จ่ายออกที่สอบทานผ่าน − รับคืนทั้งหมด** (`queries.is_return`)

ใบรับคืนคือชนิด 32 ขาเข้า สอบทานไม่ผ่านเสมอ เพราะเครื่องของ Stock5 ไม่รับรอง
การเคลื่อนไหวขาเข้า ถ้านับตามสถานะอย่างเดียว ของที่จ่ายแล้วถูกคืนจะนับเป็นการใช้เต็ม

ข้อมูลจริงของห้องจ่ายยาผู้ป่วยใน (I2) ใน 24 เดือน

| | มูลค่า |
|---|---:|
| จ่ายจากล็อตจริง | ฿244.8 ล้าน |
| จ่ายบนล็อต "." (สอบทานผ่าน) | ฿54.1 ล้าน |
| รับคืนบนล็อต "." (99.95% ของรับคืน) | ฿54.5 ล้าน |
| **ยอดใช้สุทธิ** | **฿244.4 ล้าน** |

ล็อต "." ไม่ใช่ล็อตยาจริง ของที่จ่ายและรับคืนบนล็อตนี้หักล้างกันเกือบพอดี ในนี้มี
คู่จ่าย-คืนวันเดียวกันจำนวนเท่ากัน 4,891 คู่ ฿12.2 ล้าน เช่น จ่าย METHYLPREDNISOLONE
1,000 ขวดแล้วคืน 999 ขวดในนาทีเดียวกัน — ไม่ได้แปลว่ามียาคืนจากหอผู้ป่วย ฿54.5 ล้าน
นับแบบไม่หักจะได้ ฿298.9 ล้าน เกินจริง 22%
